# 呐喊跳跳

一个以麦克风音量代替按键输入的浏览器跑酷原型。当前版本刻意保持最简视觉，只实现核心游戏闭环。

## 项目结构

```text
src/
├── audio/MicrophoneInput.ts      # 麦克风权限、音量采样、环境音校准
├── input/VoiceJumpDetector.ts    # 阈值、回落解锁、触发冷却
├── game/Game.ts                  # 固定时间步游戏循环、绘制、碰撞与计分
├── game/physics.ts               # 短长跳物理、加速曲线，供游戏和模拟共用
├── game/ObstaclePlanner.ts       # 模拟起跳窗口并约束连续障碍间距
├── main.ts                       # 串联声音输入和游戏状态
└── styles.css                    # 最低限度的页面样式
```

## 本地运行

```bash
npm install
npm run dev
```

打开终端显示的本地地址，点击“开启麦克风并开始”，授权后保持安静约 1.2 秒完成环境音校准。也可以按空格键测试跳跃。

## 当前试玩规则

声音越过阈值立即起跳，起跳后前 150ms 的持续声音会增加上升高度；松开后不能重新增加高度。下降重力为 5400，大于普通上升重力 2400，纯短跳约 0.50 秒，最长跳约 0.63 秒。声音回落有 80ms 容错，所以实际短喊时长会比纯短跳稍长。轻点／按住空格也可对照试玩，按住不会自动连跳。

行进速度按有效游戏时间从 390 平滑接近 660，切到后台不会推进游戏。障碍生成使用相同的物理步进模拟短跳、长跳，分别保留约 180ms 到至少 120ms 的起跳窗口；在前一跳最晚落地和下一跳最早起跳之间至少预留 180ms。难度逐渐增加，但不无限压缩操作时间。窗口是物理模型中的有效输入时间，不是对所有设备音频延迟的保证。

`npm test` 验证声音回落、短长跳、1500 个候选障碍的窗口和恢复间隔，以及三种操作方式各连续通过 300 个障碍。测试需要支持直接读取 TypeScript 的 Node.js（当前使用 Node 25）。`npm run build` 做类型检查和生产构建。

## 后续安卓封装

核心代码没有依赖浏览器外框。确认玩法后可加入 Capacitor，将 `dist/` 作为 WebView 内容封装为 Android 应用，再补充原生麦克风权限配置和真机灵敏度测试。

## GitHub Pages 发布

仓库 Settings → Pages 的 Source 选择 GitHub Actions。推送到 `main` 后自动安装依赖、测试、构建并发布 `dist/`，也可以手动运行 Deploy game to GitHub Pages。构建使用相对资源路径，支持仓库子目录。

公开页面需要使用 HTTPS。手机浏览器打开页面，点击开启麦克风并允许权限；建议横屏试玩。音频只在设备本地计算音量，不录制、不上传。Android / iPhone 真机和微信内置浏览器的兼容性仍需实际验证。
