# 呐喊跳跳

一个以麦克风音量代替按键输入的浏览器跑酷原型，全程采用 SunnyLand 场景与巡逻动物，角色暂时保留马里奥身体和真人头像组合。

## 项目结构

```text
src/
├── audio/MicrophoneInput.ts      # 麦克风权限、音量采样、环境音校准
├── input/VoiceJumpDetector.ts    # 阈值、回落解锁、触发冷却
├── input/PointerJumpInput.ts     # 触屏、鼠标按下及释放、取消处理
├── game/Game.ts                  # 固定时间步游戏循环、绘制、碰撞与计分
├── game/Adventure.ts             # 当前试玩的二段跳、平台、仙人掌片段与提速轨迹
├── game/physics.ts               # 短长跳物理、加速曲线，供游戏和模拟共用
├── game/SceneRenderer.ts         # 多层背景、精灵动画、头像与身体合成
├── game/SunnyLand.ts             # 原版场景 PNG、视差背景、图块地面与地刺/木平台
├── game/MineScenery.ts           # 原生矿壁图块、嵌入式木撑、单层慢速滚动与矿灯
├── game/ObstaclePlanner.ts       # 模拟起跳窗口并约束连续障碍间距
├── main.ts                       # 串联声音输入和游戏状态
└── styles.css                    # 最低限度的页面样式
```

## 本地运行

```bash
npm install
npm run dev
```

打开终端显示的本地地址，轻点游戏画面即可开始：轻点短跳，长按长跳；鼠标左键和空格键也支持同样操作。无需开启麦克风。要使用声音控制，点击“开启麦克风并开始”，授权后保持安静约 1.2 秒完成环境音校准。

屏幕操作按下即起跳，前250ms按住可增加高度，松开立即停止加成；一直按住不会自动连跳。手指移出游戏画面后松开、触控取消或切到后台都会释放按住状态；页面按钮不会触发跳跃。失败后轻点画面或点击“重新开始”可再玩。

## 当前本地试玩：平台与喷气二段跳

使用 Ansimuz 的 SunnyLand 蓝天绿野、SunnyLand Forest 金色密林，以及用同包原始图块拼成的地下矿道三种场景。矿道采用参考截图中的同款原始元素：连续棕色细岩壁、嵌入墙面的完整斜木撑、矿灯、藤蔓、壁生植物和零星砖块碎片；不直接使用截图。岩壁与全部墙面装饰统一按卷轴速度的6%慢速移动，不再叠加相似远中景、不绘制空洞房间或独立门框。四组1024像素装饰布局以固定世界坐标连接，灯光稳定、不闪烁；图块保持2倍整数像素，地面碎石位于可行走线下。背景木撑与可踩的横向平台区分，不参与碰撞。

每套保持22秒，再用6秒整帧交叉淡入下一套，按绿野→密林→矿道→绿野顺序84秒循环；暂停和失败时停止变化。不再切换春夏秋冬，也不启用旧雨雪背景。PNG 原样保留，通过 Canvas 取样与重复拼接，素材与授权见 [SunnyLand 来源说明](public/assets/sunnyland/SOURCES.md)。背景自然延伸至地面，不增加绿色或黄色隔离色带；近处装饰减少，但不整体降低背景饱和度。撤去危险物的粗描边、红色底线和平台的额外绿色顶线。平台保留横向木平台原图；固定危险物随场景绑定材质：蓝天绿野为楔形水晶尖刺，金色密林为削尖木桩刺，矿道为灰色岩石尖刺，由 Canvas 绘制像素轮廓。形状与颜色跟随背景平滑过渡，碰撞外框不变，未增加描边或色带。长危险带也使用同一材质，单条计一次分，不拼接不同类型。角色、声控和跳跃物理保持不变。

平台和危险物不显示悬浮文字标签，通过颜色和轮廓区分。操作说明保留在画面外，分数、阶段和剩余跳跃次数保留在顶部。

动物采用同系列负鼠（6帧行走）和蜗牛（4帧爬行），帧速率分别为6和4帧/秒。在出生中心左右22–30像素内匀速往返，完整周期2.0–2.4秒、每1.0–1.2秒到边界转身，世界巡逻速度约37–60像素/秒；范围相对地面而非屏幕固定。符合条件的片段以35%候选概率替换一只动物，每段最多一只，不再保证每段出现。实际比例受物理验证影响，样本约占危险物四分之一。宽二段跳危险带保留静态连续性。动物仍要跳过，不可踩踏。随机路线验证、碰撞、绘制和计分共用有效游戏时间下的巡逻位置，暂停或失败时位置及动画一起停止。整体跑道速度保持慢起步曲线。

以下四季实现仅保留代码与回归测试，当前游戏已不启用：四季采用鲜艳的像素配色，减弱浅色地平线叠层：春季蓝天粉花与鲜绿草地，夏季亮蓝天空与浓绿植被，秋季橙红天空与金黄草地，冬季蓝天白雪与蓝色冻土。草皮、表层土和深层土都随季节连续变色；雨天保留轻微暗化，不整体褪成灰色。

背景按有效游戏时间循环春夏秋冬，每季18秒，最后8秒平滑过渡到下一季（包括冬到春）。春季樱花树与郁金香、夏季棕榈和竹丛及向日葵、秋季枫树和银杏及金色草穗、冬季裸枝积雪与雪山共用连续视差场景。不同品种有独立的树干、枝叶和花朵轮廓，并非同一植物换色；植物交叠渐变，滚动元素固定世界编号，不在拼接处重排。夏秋有渐强渐弱的像素阵雨，冬季转为落雪；天气仅绘制在背景层，不遮盖平台、障碍及角色。背景变化不影响平台、碰撞和跳跃规则，暂停或失败时季节同样停止。

请通过 `npm run dev` 提供的 HTTP 地址访问，不要直接双击源码 `index.html`。当前版本默认使用平台与二段跳路线，未上传线上。

点击／空格／原有声音阈值均可起跳。第一跳保留轻点短跳、按住增高；腾空后松开再触发可执行一次固定冲量的二段跳，脚下显示蓝黄像素喷气，第三次输入无效。两次起跳最短间隔100ms；声控仍使用原来的280ms冷却和安静重置，尚未加入专用鼓掌检测。

横向木平台可从下方穿过、从上方落稳，落地或落上平台补满两次跳跃；走出平台后只剩一次空中补救。左上角显示剩余次数，另有平台着陆、二段跳、越障得分反馈。连续地刺带整段危险，不要在尖刺缝隙中落脚。

画布由900×420增高至900×560，地面从350下移至480，保留角色与障碍物原有尺寸，增加130像素头顶空间。障碍包括仙人掌、荆棘簇、尖顶晶石和尖刺；移除了容易误认为地面的方形木箱与石块。平直的绿色顶面只用于可落脚平台，其余均为危险物。此次外观替换保留障碍尺寸、碰撞范围和关卡节奏。

速度从300缓慢起步，20秒约321、30秒约343、60秒约432，随后平滑接近924；距离使用同一曲线的解析积分。难度按有效游戏时间分四段：0–18秒热身、18–40秒组合、40–65秒攀升、65秒后挑战。前两段只有独立危险物，再到间隔双障碍，组合阶段才加入平台与二段跳长带。九类正式路线为双平台接力、连续宽危险带、间隔双障碍、三连障碍、三级高台、落脚点接二段跳，以及先升后降（72→126→64）、高台下坡（72→140→208→136）、低谷再爬升（72→40→112）。新增路线分别从组合、挑战、攀升阶段进入随机池，平台高度和间距继续受可通行校验约束。后期逐渐解锁复杂片段、缩短单跳间隔和平台落脚长度、把基础片段周期从4.3秒缩到3.2秒；高低路线额外留出0.5秒，高台下坡额外留出1秒；高度最高208像素。宽危险带计算考虑角色自身宽度，避免低速增加清障时间造成无解；仍验证单次长跳不能取代二段跳。每段保留参考通关动作用于回归验证，不用于自动控制玩家。该版仍未加入专用鼓掌识别。

每局默认使用新的随机序列：在当前难度允许的片段池内洗牌抽取，不再固定轮换；每组危险物类型独立抽取，片段周期额外浮动±0.25秒，片段内部距离、宽度、横向位置和平台高度也在范围内扰动（平台高度±14像素，最高可到222像素）。宽危险带保持连续，不随机出安全缝隙；普通平台接力下方的危险物不得伸出最后平台的末端。每个候选片段用游戏同一物理模型检查每次操作独立±20ms的组合误差、四个帧相位、轻点和短暂按住、全部平台落脚及下一段前的落地恢复；失败最多重试8次，再使用通过同样检查的保底片段。构造器可注入随机种子用于复现测试，但正常游戏每次重开会重新生成。随机生成回归测试涵盖1000段、5条不同种子的连续路线和极端随机输入。

`tests/adventure.test.mjs` 验证喷气与次数恢复、平台承托、走出边缘、单跳无法跨越宽障碍、六种组合在不同速度/难度及前后20ms整体时序偏移下可通过、连续150段渐进路线衔接、后期操作密度增长和声音输入。旧路线及指针输入的回归测试仍保留；物理模型通过不代表已验证所有设备的音频延迟。

## 上一版基础规则（保留代码及回归测试）

角色在待机和游戏中使用 `图片库/正常付饶.jpg`，碰撞失败时切换为 `图片库/失败付饶.jpg`，重新开始恢复正常头像。头像圆形裁切后与马里奥腿部组合，跑步循环三帧、空中使用跳跃姿势；原始图片保留。角色尺寸由42×48放大到60×68，面积约两倍，碰撞范围同步调整并重新检查可通过性。

背景包括分层移动的云、山丘、灌木及砖地。五种障碍外形分别为小怪兽、龟壳、管道、砖堆和乌龟，尺寸按类型变化。障碍宽、高均按基础尺寸的1.3倍生成，即比上一版的2倍尺寸缩小35%（保留65%），实际碰撞范围同步缩小；高或宽的障碍需要长跳。生成时仍保留落地恢复间隔。图片来源见 [素材说明](public/assets/mario/SOURCES.md)。

声音越过阈值立即起跳，起跳后前 250ms 的持续声音会增加上升高度；松开后不能重新增加高度。加成期间上升重力为 500，普通上升重力为 2400，下降重力为 5400。纯短跳约 0.50 秒，最长跳约 0.81 秒。声音回落后 30ms 停止加成，连续安静 80ms 才允许再次触发，两种时间独立计算，避免短喊被过度延长。轻点／按住空格也可对照试玩，按住不会自动连跳。

行进速度按有效游戏时间从 390 平滑接近 660，切到后台不会推进游戏。障碍生成使用相同的物理步进模拟短跳、长跳，每个障碍必须有约 180ms 到至少 120ms 的长跳起跳窗口；只有短跳同样满足窗口要求时才记录短跳可用。放大后的障碍不再保证均可短跳通过。在前一跳最晚落地和下一跳最早起跳之间至少预留 180ms。难度逐渐增加，但不无限压缩操作时间。窗口是物理模型中的有效输入时间，不是对所有设备音频延迟的保证。

`npm test` 验证声音回落、短长跳、1500 个放大障碍的尺寸、窗口和恢复间隔，以及优先短跳、全部长跳、混合时长三种策略各连续通过 300 个障碍（无短跳窗口时选择长跳）。测试需要支持直接读取 TypeScript 的 Node.js（当前使用 Node 25）。`npm run build` 做类型检查和生产构建。

## 后续安卓封装

核心代码没有依赖浏览器外框。确认玩法后可加入 Capacitor，将 `dist/` 作为 WebView 内容封装为 Android 应用，再补充原生麦克风权限配置和真机灵敏度测试。

## GitHub Pages 发布

日常修改只在本地实施和验证；只有用户明确要求上传、推送或发布时才执行 `git push` 或触发线上部署。

仓库 Settings → Pages 的 Source 选择 GitHub Actions。推送到 `main` 后自动安装依赖、测试、构建并发布 `dist/`，也可以手动运行 Deploy game to GitHub Pages。构建使用相对资源路径，支持仓库子目录。

公开页面需要使用 HTTPS。手机浏览器打开页面，点击开启麦克风并允许权限；建议横屏试玩。音频只在设备本地计算音量，不录制、不上传。Android / iPhone 真机和微信内置浏览器的兼容性仍需实际验证。
